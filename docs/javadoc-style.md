# LinkForge Javadoc 编写规范

Javadoc 的核心作用是**记录仅通过类型、方法签名无法明确判断的调用契约**。不要简单复述类名，也不要描述容易随代码实现变动的执行步骤。

## 必须编写 Javadoc 的场景

- `application.port.in` 包下的用例接口、命令对象、返回模型
- 跨进程、跨数据库、跨消息队列的出站端口接口
- 可复用的领域类型，以及包含非直观不变规则的值对象
- 具备幂等、事务、并发、缓存、重试、顺序保证等特殊语义的实现类

简单的控制器、数据库行模型、Mapper、仅用于依赖注入的配置类，**通常不需要写 Javadoc**，除非它们包含上述需要明确的契约。

## 编写内容要求

1. 第一句话直接说明**对调用者的保证**，不要重复标识符名称
2. `@param` 需写明：允许的值范围、格式、单位、是否可为空，不要只写 “用户 ID” 这类无意义描述
3. 非 `void` 方法必须用 `@return` 说明业务含义，包括空值、空集合、拒绝结果的场景
4. 写明调用者需要处理的**业务异常**，不要罗列程序错误、空指针等不可恢复异常
5. 时间必须标注时区 / 时间基准；标识符需说明幂等性、关联关系等语义
6. 影响一致性、性能的实现细节用 `@implNote`；存在误用风险的说明用 `@apiNote`
7. 字面值用 `{@code ...}` 包裹；关联稳定的 Java 类型用 `{@link ...}`；不写无法被代码验证的承诺
8. 行为变更时，必须同步更新注释与测试；过期失效的 Javadoc 按 Bug 处理

## 校验规则

执行 `mvn verify` 会自动运行 JDK DocLint 检查：

- HTML 格式、引用、标签、语法出现警告会直接导致构建失败
- 暂不通过工具强制检查所有缺失注释，避免为内部样板代码生成无价值注释
